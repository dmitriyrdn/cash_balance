# Cash Balance

Личное Android-приложение для учёта денег на нескольких счетах. Интерфейс на английском, Kotlin + Jetpack Compose, Android 8.0 (API 26) и новее.

## Возможности

- **History** — история операций по дням, общий остаток, выданные займы и фильтр по счёту. Повторное нажатие на выбранный счёт снимает фильтр. Верхняя карточка показывает общий остаток всех видимых счетов независимо от фильтра списка.
- **Balances** — остатки по счетам и список должников, откуда можно оформить возврат займа.
- **Analytics** — расходы по категориям, поступления и средние курсы выполненных обменов за месяц или всё время. Суммы приводятся к базовой валюте по загруженным курсам; цвет сегмента диаграммы соответствует счёту.
- **Settings** — счета, их цвета и видимость, категории расходов, базовая валюта и обновление курсов.
- **Редактор** — расход (Spend), пополнение (Add), перевод (Move), обмен (Exchange), выдача займа (Lend), возврат (Repaid). Поддерживает дату, комментарий и калькулятор в поле суммы.

У каждого счёта одна валюта. Move переводит между счетами в одинаковой валюте, Exchange — в разных. Редактор проверяет достаточность средств, а для возврата займа — сумму долга. При редактировании существующая операция исключается из расчёта доступных средств.

## Фильтры и навигация

- В аналитике есть **All accounts** и отдельные видимые счета. Фильтр применяется к расходам, поступлениям, категориям и статистике обменов. Перевод/обмен относится к обоим участвующим счетам.
- Нажатие на категорию открывает её **расходы** за выбранный период, от новых к старым. «No category» открывает расходы без категории. Поступления и переводы в этот список не попадают.
- Счёт наследуется из аналитики. Внутри категории можно выбрать другой счёт или All accounts; при возврате в аналитику сохраняется последний выбор. Период меняется на основном экране аналитики.
- Из списка категории можно открыть, изменить или удалить операцию. Кнопка Back to analytics и системная кнопка «Назад» возвращают к диаграмме; из редактора «Назад» возвращает в исходный список.
- Новая операция через `+` на экране History использует счёт из фильтра и его валюту. Без фильтра используется первый видимый счёт. Создание на вкладке Balances сохраняет прежнее поведение; возврат долга подбирает счёт по валюте долга.
- Закрытие, сохранение или удаление операции возвращает к сохранённой позиции списка. Если после изменения строки исчезли, список ограничивает позицию доступными элементами. Фильтры и позиции экранов также сохраняются при переключении вкладок. Это состояние интерфейса, а не настройки в файле данных.
- Для Note клавиатуре передаётся режим заглавной буквы в начале предложения. Пользователь может отключить Shift; введённый текст принудительно не переписывается. Поддержка режима зависит от клавиатуры.

## Данные и расчёты

Все данные хранятся только в приватном каталоге приложения на телефоне, в `files/data.json`. Синхронизации, аккаунта пользователя и встроенного экспорта нет. Удаление приложения удаляет локальные данные.

- `Data`: счета, категории, операции, базовая валюта, кэш курсов и время их обновления.
- `Tx`: сумма и валюта, исходный/целевой счёт, тип, дата, категория, контрагент и комментарий. Суммы операций — `BigDecimal`.
- Балансы и долги не сохраняются отдельно: они каждый раз вычисляются из журнала операций. Сохранение и удаление операции пересчитывает результат.
- Скрытый счёт остаётся в журнале и расчётах его баланса, но исключается из выбора счетов и общих отображаемых остатков. В истории/аналитике остаются операции, касающиеся хотя бы одного видимого счёта.
- Счёт с операциями нельзя удалить или изменить его валюту. Удаление категории переводит её расходы в «без категории».
- Курсы загружаются с `https://open.er-api.com/v6/latest/USD`, автоматически при запуске, если кэш старше шести часов, и вручную. Финансовые данные туда не отправляются. Без сети журнал работает, но обновление курсов недоступно.
- Общие суммы используют текущий кэш курсов, а не исторический курс даты операции. Валюты без доступного курса не включаются в итог; история показывает предупреждение. Средний курс обменов — отношение суммарных объёмов валют, а не простое среднее курсов отдельных операций.
- Файл записывается через `AtomicFile`. При ошибке разбора исходные байты сохраняются как `data-broken-<timestamp>.json` и открывается пустой журнал со счётом Wallet.

## Структура проекта

| Файл | Назначение |
| --- | --- |
| `Ledger.kt` | Модель, JSON, балансы, долги, фильтрация, создание операции, калькулятор, даты и средние курсы |
| `MainActivity.kt` | Хранилище, загрузка курсов, навигация, история, остатки и настройки |
| `Analytics.kt` | Период и счёт аналитики, диаграмма категорий, список расходов категории и статистика обменов |
| `Editor.kt` | Создание/редактирование операции, проверки, калькулятор и выбор даты |
| `app/src/test/` | Модульные тесты расчётов и фильтров, тесты интерфейса Compose на Robolectric |

Навигация реализована состоянием Compose без отдельного navigation-компонента. `SaveableStateHolder` хранит состояние вкладок, пока редактор временно заменяет основной экран. Списки имеют `rememberLazyListState` и стабильные ключи строк.

## Сборка и тесты

Нужны JDK 17+, Android SDK Platform 35, Build Tools 34.0.0 и доступ к Maven/Google/Gradle для первой загрузки. Gradle 8.11.1 загружается wrapper-скриптом. Задайте `ANDROID_HOME` или `sdk.dir` в локальном `local.properties`.

```sh
bash gradlew testDebugUnitTest assembleDebug lintDebug
```

В Windows можно использовать `gradlew.bat`. Результаты:

- APK: `app/build/outputs/apk/debug/app-debug.apk`.
- Тесты: `app/build/reports/tests/testDebugUnitTest/index.html`.
- Lint: `app/build/reports/lint-results-debug.html`.

UI-тесты используют Robolectric (API 28) и не требуют эмулятора. `LedgerTest` проверяет расчёты и совместимость JSON; `FilteringTest` — счета, периоды, категории и начальный счёт операции; `NavigationTest` — наследование фильтра и возврат к позиции списка.

Для ручной проверки на телефоне:

1. Создать два счёта и расходы одной категории на обоих, в текущем и предыдущем месяце.
2. В аналитике выбрать счёт и период, открыть категорию: сверить набор операций и суммы. Переключить счёт внутри, затем вернуться назад.
3. Из середины истории и списка категории открыть операцию; проверить возврат после закрытия, сохранения и удаления, включая системную кнопку «Назад».
4. В истории выбрать второй счёт, нажать `+` и создать операцию: проверить счёт и валюту. Снять фильтр и повторить.
5. В пустом Note проверить заглавную первую букву на используемой клавиатуре.

## Выпуск APK

`release.sh` — существующий сценарий для Git Bash на компьютере владельца. Он содержит локальные Windows-пути к JDK, SDK и GitHub CLI. Перед запуском нужно увеличить `versionCode`/`versionName`, закоммитить изменения и при необходимости адаптировать пути. Скрипт запускает тесты, собирает release APK, отправляет коммит и создаёт GitHub Release.

Release сейчас подписывается **debug-ключом компьютера сборки**. Для обновления уже установленного приложения нужен тот же ключ. APK, собранный в другой среде, не заменит установленную копию с другой подписью. Не удаляйте приложение ради установки такой сборки без сохранения данных.
